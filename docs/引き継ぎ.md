## 次にすること

1. **ダミー書類を用意する（へのへのもへじ医師作成の診断書など）**
   - 架空の値で書いた書類を、事務所のスキャナでOCRしてPDFにする（実物の事件記録は使わない）
   - ほしいもの：交通事故証明書、診断書、後遺障害診断書、診療報酬明細書（入院・外来、2か月分以上）、調剤報酬明細書、
     自賠責の支払通知・後遺障害の認定結果、源泉徴収票、休業損害証明書、修理見積書・領収書
   - できれば手書き欄のある診断書と、テキスト層のないスキャン（OCRなし）も1通ずつ
   - `koutsu-sojyou/tests/fixtures/` に置く → それに合わせて rules.py を直し、テストにする
2. **Bedrock の設定を教えてもらう**：今動いているモデルID（推論プロファイル）・リージョン・AWSプロファイル名。
   既定値 `jp.anthropic.claude-sonnet-4-6` は推測。設定したら、ダミー書類で「AIで読む」を試す
3. **Windows で exe を作る**：Actions →「exe版のビルド」→ Run workflow。zip を `C:\koutsu` に展開し、送るに登録.bat から試す
4. **tokumeiocr 側**：exe を作り直して `tokumeiocr.exe ocr-text` を PaddleOCR 実機で試す。訴状アプリからテキスト層のないページを読めるか確かめる
5. 2 つのブランチを main に入れる（PR）
6. 必要なら：死亡事案（shibou）の入力欄。今は「詳細（case.json）」で直接書く

## 決めたこと（理由つき）

- スキルのスクリプトは書き換えない。アプリの入力（`事件フォルダ\訴状\case.json`）はスキルと同じ形なので、**Claude Desktop のスキルからも使える**
- 合計額は Web版Excel で見て打ち込むのをやめ、xlsx の数式を formulas で計算する（期待値は scripts/lo_expected.py で LibreOffice から作る。英語ロケールだと DATEVALUE("2020/3/31") が #VALUE! になるので必ず日本語ロケール）
- PaddleOCR はアプリに同梱せず、tokumeiocr を呼ぶ（exe が小さいまま、OCR中の接続遮断もそのまま）
- AI は押したときだけ送る。答えも規則と同じ確認画面を通す。送った記録は `_訴状アプリ\AI送信記録.txt`
- anthropic SDK は 1.x に固定（Bedrock が API バージョン 2026-10-21 を受け付けるのは Claude 4.7 以降）
- PyMuPDF は 1.28.2（2.x は onnxruntime＝利用状況の送信機能つきを引き込む）。そのため Python は 3.12〜3.14（numpy・scipy の都合）
- 交通事故証明書の甲は既定で被告（第一当事者）。どちらが原告かは要判断として画面で選ぶ

## 気をつけること

- 規則の精度は、実物のスキャンを見るまで分からない。拾えなかった項目は手入力になるだけで、誤って入ることはない（○にしたものだけ入る）
- 事案の概要 L68・M68（入通院日数の表示用）は formulas で計算できない。合計には使わないので影響なし
- exe の zip は Linux で約200MB（numpy・scipy が大半）

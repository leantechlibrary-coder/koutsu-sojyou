# koutsu-sojyou — 交通事故の訴状（共通書式）アプリ

Claude Desktop のスキル [kotsu-sojou](kotsu-sojou/SKILL.md) を、[youikuapp](https://github.com/leantechlibrary-coder/youikuapp)・[tokumeiapp](https://github.com/leantechlibrary-coder/tokumeiapp) と同じ
**PCの中だけで動くアプリ**にしたものです。

- 事件フォルダを右クリック →「送る」→「交通事故の訴状を作る」で始められます
- 証拠PDF（スキャナでOCRしたもの）から、事故日・当事者・レセプト・支払額などの**候補を自動で拾い**、確認画面で ○／× を付けて入力に入れます
- 足りないところを入力し、人が決める項目（過失割合、自賠責の充当方法、等級など）を決めて、**共通書式（xlsx）と訴状（docx、mints添付用）**を作ります
- 合計額（損害額一覧表 F74・F105）は、出した xlsx の数式をアプリが計算して訴状に入れます（Web版Excel で見て打ち込む手間がなくなります）
- テキスト層のないページは [tokumeiocr](https://github.com/leantechlibrary-coder/tokumeiocr)（PaddleOCR）で読みます
- 設定で使うにしたときだけ、**Bedrock（Claude Sonnet 4.6、ZDR）**で読み取り・補足主張の下書きができます
- **exe版**（Python 不要）を GitHub Actions で作れます

## スキルとの関係

スキルのスクリプト（`kotsu-sojou/` の build_kyoutuu.py・build_sojou.py など）は**書き換えずにそのまま**使います。
アプリは、スキルで Claude と人がしていた部分を画面にしたものです。

| スキルでの仕事 | 担当 | アプリでは |
|---|---|---|
| 証拠PDFを読んで case.json を書く | Claude | 規則で候補を拾う（`rules.py`）→ 確認画面で人が ○／× ＋ 入力の画面。AIで読むこともできる（任意） |
| 補足主張・経緯の下書き | Claude | 入力欄に手で書く。AIで下書きもできる（任意） |
| セルへの流し込み・証拠番号・訴状 | スクリプト | 同じスクリプト（`core.py` から呼ぶ） |
| 合計の計算 | Web版Excel → 人が転記 | アプリが xlsx の数式を計算（`formulas`）。Excel と同じ値になることをテストで確かめている |
| judgment の決定 | 人 | 「⑥ 判断・不明点」で人が決める |

入力の本体は `<事件フォルダ>\訴状\case.json` で、スキルの case.json と同じ形です。アプリで作った case.json をスキルで使うことも、その逆もできます。

## 使い方（右クリック）

1. 初回だけ、exe版は `送るに登録.bat`、Python版は `setup.bat` → `送るに登録.bat` をダブルクリックする
2. 事件フォルダ（証拠PDFを入れたフォルダ。サブフォルダも見ます）を右クリック →（Windows 11 は「その他のオプションを確認」→）「送る」→「交通事故の訴状を作る」
3. ブラウザで画面が開く。上から順に進める

| 画面 | すること |
|---|---|
| ① 証拠を読む | 「まだ読んでいない証拠を全部読む」→ 1通ずつ開き、拾った候補を ○／× にして「反映」。左にページが出て、「ページで見る」で拾った場所に枠が出る |
| ② 事故・当事者 | 事故日時・場所・態様、関係車両、責任原因、提出先・訴状の日付・当事者、証拠の一覧 |
| ③ けが・治療 | 被害者・傷病名、治療期間（入院と通院は分ける）、症状固定、後遺障害、治療費等集計表（レセプト）、通院交通費 |
| ④ 損害 | 損害項目（慰謝料は `akai` で赤い本の自動計算）、自賠責保険金（受領ごと・充当方法）、休業損害（`shufu` で主婦のセンサス）、逸失利益、過失相殺・素因減額 |
| ⑤ 物損 | 修理費・レッカー・代車など、既払、過失相殺、弁護士費用 |
| ⑥ 判断・不明点 | 足りない入力、人が決める項目（judgment）、不明点（todo）。決めたら「決めた」 |
| ⑦ 訴状の文章 | 補足主張・本訴に至る経緯（AIで下書きもできる）、訴状本文にだけ出る証拠、附属書類 |
| ⑧ 書面を作る | 共通書式 → 合計の計算 → 訴状。合計額・証拠番号・出したファイルが出る |
| 設定 | 事務所の情報（訴状の作成者欄）、AI（Bedrock）、tokumeiocr の場所 |
| 詳細（case.json） | 画面に欄のない項目（死亡事案の `shibou`、代車費用の日額×日数など）を直接直す。書き方は [SKILL.md](kotsu-sojou/SKILL.md) と同じ |

4. 終わったら「終了」を押す。入力は画面を移るとき・終了するときに自動で保存されます（「保存」ボタンと Ctrl+S も使えます）

### できるもの

```
<事件フォルダ>\訴状\case.json                      入力の本体（スキルと同じ形）
<事件フォルダ>\訴状\原告一覧表.xlsx                 共通書式（事案の概要・損害額一覧表・治療費等集計表・相続等一覧表）
<事件フォルダ>\訴状\原告一覧表_証拠リスト.json       証拠説明書の材料（shoko-setsumeisho スキルに渡す）
<事件フォルダ>\訴状\訴状.docx                       訴状（mints添付用。「第１ 請求の趣旨」から）
<事件フォルダ>\訴状\訴状_mints入力メモ.md           mints に入れる訴額・遅延損害金の起算日など
<事件フォルダ>\_訴状アプリ\                         読み取りのキャッシュ、確認の状態（state.json）、AI送信記録.txt
```

訴状のPDF化はアプリではしません。作成者情報を残さない方法でPDFにしてください（mintsマニュアル別紙3）。

## 証拠PDFからの読み取り

### 文字の取り出し

- スキャナでOCRしたPDFは、テキスト層を文字ごとの位置つきで読みます（ネットワークは使いません）
- 全角の数字・英字はそろえ、スキャナのOCRがよく入れる字間の空白（「令 和 6 年」）は消します。表で左右に分かれた「項目名」と「値」は同じ行としてつなげます
- 文字がほとんど取れないページ（テキスト層がない）は、tokumeiocr の `ocr-text` で読みます（1ページ十数秒）。tokumeiocr がないPCでは、そのページは手入力にまわします
- 読んだ結果は `_訴状アプリ\cache\` に残すので、2回目からは一瞬です

### 書類ごとに拾う項目（規則。AIは使わない）

書類の種類は、表題の語のうち文書のいちばん前に出てくるもので決めます。

| 書類 | 拾う項目 |
|---|---|
| 交通事故証明書 | 事故日・時刻・場所、甲・乙の氏名・住所・車種・車両番号（甲は既定で被告。どちらが原告かは要判断）、証明日 |
| 診療報酬明細書・調剤報酬明細書 | 1か月分ごとに1行：医療機関、年月（R6.1）、入院・通院日数、金額（円がなければ点数×10円で、要確認） |
| 診断書 | 傷病名、入院・通院の期間 |
| 後遺障害診断書 | 傷病名、症状固定日 |
| 後遺障害の認定結果 | 等級（後遺障害慰謝料を赤い本で計算する等級として。要判断） |
| 保険金の支払通知 | 自賠責なら受領日・受領額（payments）、任意保険なら既払金（治療費か、それ以外かは要判断） |
| 源泉徴収票 | 支払金額（逸失利益の基礎収入、休業損害の日額＝÷365。どちらも要判断） |
| 休業損害証明書 | 休業期間の終わり、職種 |
| 見積書・領収書・請求書 | 総額（税込）。物損のどの項目かを選ぶ（要判断） |
| どの書類でも | 証拠キー・標目・作成日・作成者・立証趣旨の下書き |

拾った候補はそのままでは入力に入りません。○にしたものだけが入ります。同じ候補を2回入れても二重にはなりません。

規則は、実物の書類に合わせて直していきます。**架空の値で書いた書類をスキャナでOCRしたPDF**を `tests/fixtures/` に置いてもらえれば、それで規則を直し、テストにします（実物の事件記録はリポジトリに入れません）。

### AI（Bedrock・Claude Sonnet 4.6）を使う

設定の画面で「Bedrock を使う」にすると、確認画面に「AIで読む」、⑦ に「AIで下書き」が出ます。

- **押したときだけ**、その書類のページ画像と文字を Bedrock に送ります。ほかのときは通信しません
- AIの答えも規則と同じ候補にして、同じ確認画面を通します。AIの「引用」がPDFの文字の中に見つからないもの、AIが「読みにくい」としたものは要確認にします
- AWS の認証は、このPCの AWS の設定（`~/.aws` のプロファイル、環境変数）を使います。設定の画面でリージョン・プロファイル・モデルID（推論プロファイル）を指定します
- 送った記録（日時・ファイル名・ページ数・モデル）は `_訴状アプリ\AI送信記録.txt` に残ります
- `anthropic` の SDK は 1.x に固定しています。Bedrock が新しいAPIバージョン（2026-10-21）を受け付けるのは Claude 4.7 以降のモデルだけなので、Sonnet 4.6 を使う間は 2.x に上げません

## 動作環境

- Windows 10/11（64bit）。Linux でも動きます
- **Python 3.12〜3.14（64bit）**（exe版なら要りません）。numpy・scipy（合計の計算に使う formulas が使う）が 3.12 以上を求めます
- ライブラリは動作確認したバージョンに固定しています。`requirements.txt` は直接使うもの、`constraints.txt` はそれらが引き込むものも含めた全部
- PyMuPDF は 1.28 にしています（2.x はレイアウト解析のために onnxruntime を引き込み、onnxruntime には利用状況を送る機能があるため）

## セットアップ（Python で動かすとき）

`setup.bat` をダブルクリックします（`.venv` を作り、`requirements.txt` のライブラリを `constraints.txt` のバージョンで入れます）。以後は `review.bat 事件フォルダ`。

## exe版（Python なしで使う）

- GitHub の Actions タブ →「exe版のビルド」→ Run workflow。できた zip（Artifacts の `koutsu-win64`）を展開し、フォルダごと `C:\koutsu` に置く（`C:\koutsu\koutsu.exe` になるように）
- `v1.0.0` のようなタグを push すると、同じものを作って Releases に zip を付けます
- 中の `使い方.txt` に同じ説明があります
- ビルドのたびに、スキルの見本（記載例1・物損・死亡）で exe と Python とで同じ合計額・証拠番号になること（記載例1は 40,142,986円）、画面のサーバーが立って証拠PDFを読めること、合言葉なしでは応答しないこと、外部に接続しないことを確かめています（`scripts/build_exe.py`）

## コマンド

```bat
review.bat 事件フォルダ               :: 画面
build.bat 事件フォルダ [--full]       :: 画面なしで、訴状\case.json から書面を作る（--full は表紙・当事者目録つき）
koutsu.exe version                    :: 同梱したライブラリ・tokumeiocr・AIの設定
```

## ファイル

```
kotsu-sojou/      スキル（Claude Desktop 用。書き換えない）。裁判所の様式（assets/）、見本の case.json
core.py           スキルのスクリプトを呼んで書面を作る。xlsx の数式を計算して合計額を出す
reader.py         証拠PDFの文字と位置を読む（テキスト層・tokumeiocr）
rules.py          書類の種類を決め、値の候補を拾う（規則）
merge.py          ○にした候補を case.json に入れる
ai.py             Bedrock での読み取り・下書き（任意）
app.py            画面のデータと処理
server.py         PCの中だけのWebサーバー（127.0.0.1、合言葉つき）
ui.html           画面
koutsu.py         入口（exe もここから）
quick.py          「送る」メニュー
koutsu.spec       PyInstaller の設定
scripts/build_exe.py      exe のビルド → 動作確認 → zip
scripts/lo_expected.py    テストの期待値を LibreOffice の再計算で作り直す（開発用）
tests/            テスト（python -m unittest discover tests）
```

## テスト

```bat
python -m unittest discover tests
```

- `test_core.py`：見本4件（記載例1・物損・確定遅延損害金・死亡）の**全セル**で、アプリの計算が LibreOffice（日本語ロケール）の全再計算と一致すること。死亡事案で、訴状の原告ごとの請求額と相続等一覧表の請求額合計が一致すること
- `test_rules.py`：合成のPDF（交通事故証明書・レセプト・診断書・認定結果・支払通知・源泉徴収票・見積書）から候補を拾い、case.json に入れられること
- `test_ai.py`：偽の Bedrock で、AIの答えの扱い（候補への変換・引用の照合・下書き）
- `test_app.py`：事件フォルダを読み、確認して入れ、書面を作るまで。サーバーの合言葉

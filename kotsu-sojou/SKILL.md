# 交通事故訴状（共通書式）作成スキル

## 役割分担（最重要）

- **Claude（あなた）の仕事**：証拠PDFを読み、事実を `case.json` に書き出すこと。補足主張・交渉経過の文章の下書き。
- **スクリプトの仕事**：`case.json` を公式テンプレの決まったセルに流し込み、証拠番号を振ること。
- **Excelの仕事**：計算。休業損害・逸失利益・過失相殺・合計はすべてテンプレの数式が出す。
- **人（Opuさん）の仕事**：`judgment` 項目の決定と、Web版Excelでの最終確認。

次のことは**しない**。

- 金額の計算（合計、日額×日数、ライプニッツ係数、過失相殺額など）。素材の数字だけ書く。
- 証拠番号（甲001など）を書くこと。証拠はキーで参照し、番号はスクリプトが振る。
- テンプレxlsxをopenpyxl等で直接開いて保存すること。プルダウン（入力規則の拡張部分）が消える。書き込みは必ず `build_kyoutuu.py` を通す。
- 判断が要る項目を黙って決めること。候補を入れて `"judgment": true` を付ける。

## 手順

1. 新件フォルダの証拠PDFをすべて読む。1通ごとに証拠キーを決める（後述）。
2. `case.json` を新件フォルダに書く。形は `case_kisairei1.json` に合わせる。
3. Opuさんに、`judgment: true` の項目と、`todo` に挙げた不明点の一覧を短く示す。決まったら `case.json` を直す。
4. 実行する：
   ```
   python <スキルフォルダ>\build_kyoutuu.py case.json <スキルフォルダ>\assets\20260514kyoutuushosiki.xlsx 原告一覧表.xlsx
   ```
   止まったら（行数超過・証拠キー未定義・全角数字混入・センサス年度なし）原因を直して再実行。警告（別紙で使われていない証拠、要確認のセンサス年度）はOpuさんに伝える。
5. 出力（`原告一覧表.xlsx` と `原告一覧表_証拠リスト.json`）を伝え、Web版Excelで確認してほしい点を挙げる：合計（人損 F74・物損 F105）、法定利率 F113、A1/B1フィルタでの非表示、最終更新日・更新者。
6. Opuさんから合計額（Web版Excelで見た F74、物損があれば F105）を聞き、訴状を作る：
   ```
   python <スキルフォルダ>\build_sojou.py case.json <スキルフォルダ>\office.json 訴状.docx --amount 40142986
   ```
   出力は `訴状.docx` と `訴状_mints入力メモ.md`。合計額は自分で計算せず、必ずOpuさんから受け取る。
   既定はmints添付用で、「第１ 請求の趣旨」から始まり、表紙（表題〜貼用印紙額）と当事者目録は付かない（当事者はmintsのフォームに入力し、申立書に出る。裁判所の書式ページの「訴状の2ページ目以降を添付書類として」に合わせた形）。紙・旧方式用の全体版が要るときだけ `--full` を付ける。押印表示は付けない（mintsでは押印不要）。
7. 証拠説明書は `_証拠リスト.json` を shoko-setsumeisho スキルに渡して作る。

## 訴状（sojou欄）

mintsではフォームの趣旨・理由欄を「別紙請求の趣旨記載のとおり」「別紙請求の原因記載のとおり」とし、中身は添付の訴状PDFに書く運用。`build_sojou.py` が裁判所の一覧表利用版ひな型に差し込む。

スクリプトが自動で決めるもの（書かない）：
- 訴訟物の価額・貼用印紙額（民訴費用法別表第一で計算）、mintsに入れる訴額（万円・切上げ）
- 遅延損害金の利率（事故日がR2.4.1前なら年５分、以後は年３パーセント）と起算日（事故日）
- 被告が複数なら「被告らは…連帯して」、よって書きの被告ごとの根拠条文（`sekinin` から）
- チェックボックス（治療費等集計表＝レセプトがあれば、相続等一覧表＝`souzoku`、補足主張の「次のとおり」「主張一覧表」）
- 補足主張がなければ請求の原因２を削って番号を詰める
- 証拠方法の日付、見本ヘッダーの削除、作成者情報の削除（`--full` のときは当事者目録も）

`case.json` の `sojou` に書くもの（見本は `case_kisairei1.json`）：
- `date`（訴状の日付）、`court`（例：東京地方裁判所）
- `plaintiff`：`zip`・`address`・`name`。`defendants`：同じ形の配列（mints用でも、被告の数とよって書き・全体版のために書く）
- `hosoku`：補足主張 `[{"title":"事故態様","body":["段落", …]}]`。不要なら空配列
- `keii`：本訴に至る経緯の段落の配列（番号はスクリプトが付ける）
- `shucho_ichiran`・`souzoku`：真偽値
- `ev_order`：訴状本文にだけ出る証拠のキー（回答書など）。本文中の証拠は `{証:キー}` と書くと番号に置き換わる
- `fuzoku`：附属書類の行（省略時は証拠説明書・甲号証・訴訟委任状）

補足主張と経緯は文章の下書きなので、`judgment` 扱いでOpuさんに必ず見せる。

## 証拠キーの付け方

- 半角英小文字とアンダースコア。例：`jiko_shomei`、`shindansho`、`receipt_A`、`gensen`。
- 1通1キー。同じ書類の別の月のレセプトでも、ファイルが1通なら1キー。
- `evidence` の各キーに `title`（標目）、`date`（作成日 `YYYY-MM-DD`、不明なら null）、`author`（作成者）、`purpose`（立証趣旨）を書く。
- 事故記録は `kind` を付けると定型が入る（title・purpose を書かなくてよい）：

| 手元の資料 | kind | 備考 |
|---|---|---|
| 物件事故報告書（物損） | `bukken` | |
| 実況見分調書だけ（人身） | `jikkyo` | |
| 実況見分調書を含む刑事記録一式 | `keiji` | 1号証「刑事記録」。`jikkyo_author` に実況見分調書の作成者を書く → 作成者「〇〇ほか」、作成年月日は空欄 |

- 番号は別紙の読み順（事案の概要→損害額一覧表→治療費等集計表）で初出順に振られる。訴状本文にだけ出る証拠は `sojou.ev_order` に順に並べる。

## case.json の書き方

見本は `case_kisairei1.json`。主な決まりだけ書く。

- 日付は `YYYY-MM-DD`、時刻は `HH:MM`。治療費等集計表の年月だけは和暦文字列 `R6.1`。
- 金額・日数は数値。率は小数（休業率 1.0、喪失率 0.2）。
- **既払金はプラスで書く**（任意保険金(治療費)・任意保険金(その他)・自賠責保険金）。マイナスへの変換はスクリプトがする。
- `vehicles[].type` はプルダウンの表記に合わせる：普通乗用自動車／普通貨物自動車／大型乗用自動車／大型貨物自動車／普通自動二輪車／小型自動二輪車／原動機付自転車／自転車／電動アシスト付き自転車／歩行者（その他は具体的に）。最大4台。
- `sekinin[].basis` はプルダウンの表記（全角数字）：`民法７０９条`／`民法７１５条`／`自賠法３条`／`その他`。共同不法行為なら `joint` に `民法７１９条`。最大4件。
- `shogai.treatment[].type` は `入院` か `通院`。レセプト上で一括でも入院と通院は分ける。最大24行。
- `receipts` は1行1レセプト：`[医療機関, 年月, 入院日数, 通院日数, 金額, 証拠キー]`。薬局は日数 null。最大96行。
- `commute` は `[医療機関, 片道額, 証拠キー]`。最大10行。
- `songai.items[].key` は次のどれか：装具代／入院雑費／入院付添費／通院慰謝料／後遺障害慰謝料／任意保険金(治療費)／任意保険金(その他)／自賠責保険金／弁護士費用。
- **自賠責保険金**は受領ごとに `payments` で書き、`method` で充当方法を選ぶ（judgment）：
  ```json
  {"key":"自賠責保険金","method":"kakutei","payments":[
    {"date":"2024-03-15","amount":1200000,"ev":"jibai1"},
    {"date":"2025-06-30","amount":3310000,"ev":"jibai2"}]}
  ```
  - `"genpon"`：受領額の合計を元本から控除（F60に合計のマイナス、理由等に受領日・受領額）。
  - `"kakutei"`：トリセツ第4の5(4)の方式。受領日までの確定遅延損害金に先に充当し、F60には確定遅延損害金を控除した残額、G60には受領日・受領額・確定遅延損害金を入れる。どちらも**数式**で入るので、損害額を直しても再計算される。計算は遅延損害金計算機（LTL-Delay-Interest-Calc）の裁判所方式と同じ（初日算入・端数期間暦年閏年説・各区間円未満切捨て）。執行部方式の端数処理にするなら `"truncate_each": false`。
  - `"kakutei"` の元本は SUM(F55:F59)（過失相殺後から任意保険金・労災・人傷を引いた額）。弁護士費用は含めない。受領は4回まで。
  - `"kakutei"` のとき訴状は、弁護士費用（物損があれば物損も）を事故日から、残りを最後の受領日の翌日からとする2本立てになる。弁護士費用は金額（整数）で書く。
  - 旧形式（`amount` だけ）も使える（元本から控除）。
- 休業損害 `kyugyo`（最大3期間）：`end`（終期）、`daily`（日額）、`count`（`"期間"` なら終期−始期で自動、数値なら休業日数）、`rate`。始期は事故日と前期間の翌日が自動。
- 逸失利益 `issitsu`（最大3期間）：`income`（年額）、`loss_rate`、`living`、`end_age`。始期年齢は症状固定時年齢が自動。
- **主婦**：`daily` や `income` に `"shufu"` と書く。事故前年の賃金センサス（女性・学歴計・全年齢平均）から年額を引き、日額は÷365の円未満切捨て、理由等の欄も自動で入る。数字を自分で計算しない。
- **慰謝料（赤い本）**：`amount` に `"akai"` と書くと自動計算する。金額を自分で計算しない。
  - 通院慰謝料：`{"key":"通院慰謝料","amount":"akai","table":"I"}`。`table` は `"I"`（別表Ⅰ）か `"II"`（別表Ⅱ：他覚所見のないむち打ち、軽い打撲・捻挫など）で、どちらにするかは judgment。入院日数・通院期間は `shogai.treatment` と事故日から数える（通院期間＝総治療期間−入院日数）。1月＝30日の日割りで、入院＋通院は「入院期間の額＋（総治療期間の通院額−入院期間相当の通院額）」。千円未満切上げ。通院が少ないとして実通院日数で修正するなら `"hosei": 3.5`（別表Ⅰ）／`3`（別表Ⅱ）を付ける（実通院日数は治療費等集計表の通院日数の合計）。15月を超えると止まるので個別に検討。理由等の欄は自動で入る。
  - 後遺障害慰謝料：`{"key":"後遺障害慰謝料","amount":"akai","grade":11}`。併合後の等級を `grade` に書く（等級の判断は judgment）。
  - 増額事由（手術の繰り返し、悪質な事故態様など）は自動計算に入れない。主張するなら金額を数値で書き、`reason` に根拠を書く。
- 分からない値は null にして、ルートの `todo` 配列に「何が分からないか・どの証拠を見れば分かるか」を書く。推測で埋めない。

## 物的損害（busson欄）

手元の資料は、見積書、損傷部位の写真、修理済みなら領収書（請求書）、全損なら時価の資料（中古車価格の資料など）、代車・レッカーの請求書。ここから `busson` を書く。見本は `case_kisairei2.json`。物損だけの事案では `shogai`・`receipts`・`songai` は書かない。

- `items`：損害項目。`車両修理費`・`レッカー費用`・`代車費用` は定型行（78〜80行）、それ以外（`車両時価額`・`買替諸費用`・`評価損`・`休車損害`・着衣等）は自由行に8件まで。使わない定型行は空欄にされ、B1の非表示フィルタで消せる。
- 修理費の額：修理済みなら領収書・請求書の額、未修理なら見積書の額（いずれも消費税込みの総額）。どちらの資料かを `reason` に書く（例：「R7.12.10修理完了（支払未了）」）。
- **分損か経済的全損か**は judgment。修理費（見積）が時価額＋買替諸費用を上回りそうなら、両方の数字を示してOpuさんに決めてもらう。全損なら `車両修理費` は書かず `車両時価額` と `買替諸費用` を書く（両方書くとスクリプトが止まる）。時価額の根拠（どの資料の何の価格か）を `reason` に書く。
- 評価損・休車損害は認められるかどうか自体が争点になりやすいので judgment。
- 代車費用・休車損害は日額×日数で書ける：`"amount":{"daily":7500,"from":"2025-10-16","to":"2025-12-10"}`（両端を含む）または `{"daily":7500,"days":56}`。
- `kashitsu`：`{"rate":0.2,"reason":"別冊判タ39号【図番号】、修正要素…"}`（judgment）。
- `hoten`：既払。`車両保険金` は94行、それ以外（対物賠償の内払など）は自由行。**プラスで書く**（マイナスへの変換はスクリプト）。
- `sonota`：その他の項目（101〜103行）。
- `bengoshi`：`{"rate":0.1}` で控除後の10％（千円未満切捨て）を自動計算。額を決めているなら `{"amount":217000}`。
- 損傷の証拠は、保険会社のアジャスターが作った損害確認のレポートか、被害者が自分で撮った写真が多い（写真撮影報告書は作らないことが多い）。
  - レポート：`kind: adjuster`。`title` は資料の表題どおり（「損害確認報告書」「損害調査報告書」など）、`author` は保険会社名。
  - 写真：`kind: shashin`。標目「写真」、作成者は撮影者（既定は原告）、`date` は撮影日。`taisho`（撮影対象、既定は原告車）・`basho`（撮影場所）を書くと、証拠説明書の備考に「撮影対象・撮影日・撮影場所」が入る（民訴規則148条）。分からなければ `[要確認]` が入る。
- 証拠の `kind`：`mitsumori`（見積書）、`ryoshu`（領収書）、`jika`（中古車価格資料）、`daisha`（代車料金の請求書）、`tow`（レッカー代金の領収書）。標目・立証趣旨の定型が入る。`title` を書けば上書きできる。
- 訴状は物損合計（F105）を `--busson` で渡す。人損もあれば `--amount` と両方。

## 死亡事案（shibou欄）

見本は `case_shibou_rei.json`。共通書式の相続等一覧表をそのまま使う（行の追加・削除はしない）。

- 損害額一覧表は**被相続人本人の損害**だけ。過失相殺と任意保険金等の控除までで、自賠責（F60）と弁護士費用（F73）は入れない（スクリプトが止める）。F74 が「本人の損害の残元本」になり、相続等一覧表で相続分により按分される。
- `shogai`：`victim` は被相続人、`injuries` は死因、即死なら `treatment` は空配列。`shibou.date`（死亡日）を書くと、事案の概要の見出しが「死亡日」になり、逸失利益の始期年齢・ライプニッツ係数が死亡時基準になる。
- 損害額一覧表の慰謝料：`{"key":"死亡慰謝料","amount":20000000}`（46行、「死亡慰謝料（本人分）」）。入院後に死亡したなら `通院慰謝料`（入通院慰謝料）も。本人分と近親者分の配分は judgment。合計が赤い本の目安（一家の支柱2800万円、母親・配偶者2500万円、その他2000万〜2500万円）とどう違うかを実行時に表示する。
- 逸失利益：`loss_rate` 1.0、`living`（生活費控除率）と `living_reason`、`end_age`。年少者で就労開始年齢から数えるなら `start_age`（18・22）。年金の逸失利益を給与と重ねるなら期間2に `start_age`（死亡時年齢）を書く。
- `shibou.heirs`：原告を列順に `{"name","zokugara","share"}`。`share` は `"1/2"` の形。相続人でない近親者（711条類推の兄弟姉妹など）は `share` を null にして固有の損害だけ。8人まで（5人以上ならJ〜M列を再表示）。続柄はプルダウン以外の文字でもよい（計算に使われない）。`heirs_ev` に戸籍等。
- `shibou.koyuu`：固有の損害（4項目まで）`{"key":"近親者慰謝料","amounts":{"氏名":金額},"reason","ev"}`。葬儀費用は支出した原告の固有の損害に入れる。素因減額・過失相殺は本人と同じ率が入る。
- `shibou.hoten`：原告ごとの填補（3項目まで）。労災・公的年金は**受給者の列だけ**に、支給済み・支給確定分を書く（最大判平5.3.24）。事故日に元本から控除した扱い（最大判平27.3.4）で、確定遅延損害金の元本からも引かれる。`kind` は費目拘束で、`isshitsu`（遺族補償年金・遺族厚生年金・遺族基礎年金：逸失利益からだけ）か `sougi`（葬祭料：葬儀費用からだけ）。
  - **特別支給金（遺族特別支給金・遺族特別年金）は書かない**（損益相殺の対象外。最判平8.2.23）。支給決定通知に本体と並んで載っていても拾わない。
  - 葬祭料が葬儀費用を超えるとスクリプトが止める。遺族補償年金が逸失利益の相続分を超えていないかは、mints入力メモの確認欄でOpuさんが見る。
  - どの時点の支給額で書くか（提訴時の支給済み分など）は judgment。`reason` に「R7.9までの支給済み分」のように書く。
- 自賠責保険金は `songai.items` に通常どおり書く（`method` も同じ）。死亡事案では相続等一覧表38行に、相続分で割り付けて原告ごとに入る。`kakutei` なら原告ごとの元本（相続額＋固有の損害（過失相殺後）−労災等）で確定遅延損害金を計算する（P38に全体の説明と原告ごとの額）。相続人でない原告には割り付けない。
- `shibou.bengoshi`：`{"rate":0.1}`（控除後の10％、千円未満切捨て。既定）か `{"amounts":{"氏名":金額}}`。
- 物損があれば F105 が相続分で按分される（物損の弁護士費用は F104 に入れておく。相続等一覧表の物損側には弁護士費用の入力欄がない）。
- 訴状：`sojou.plaintiffs` に原告を `heirs` と同じ氏名で並べる（`zip`・`address`、未成年なら `daiinin`：「上記法定代理人親権者母　○○」）。`--amount` には損害額一覧表の **F74（本人分）** を渡す。原告ごとの請求額はスクリプトが相続等一覧表の数式を再現して出し、請求の趣旨を原告ごとに、確定遅延損害金方式なら原告ごとに起算日2本立てにする。mints入力メモの表と、Web版Excelの請求額合計（45行）を照合する。法定代理人がいれば附属書類に戸籍謄本が入る。

## judgment を付ける項目

候補を入れたうえで `"judgment": true` を付け、手順3で必ず示す。

- 責任原因の根拠条文と過失の内容
- 過失相殺率・素因減額率（`songai.kashitsu` / `soin`：`{"rate":0.1,"reason":"…","ev":[…]}`）
- 後遺障害の主張等級（自賠責と違う場合は部位・内容と理由）
- 休業損害の基礎収入の選び方（実収入か主婦センサスか、兼業主婦なら高い方）、休業日数・期間の区切り、休業率
- 逸失利益の基礎収入・喪失率・終期年齢・生活費控除率
- 通院慰謝料・後遺障害慰謝料の額と根拠（赤い本の別表、等級）
- 弁護士費用
- 自賠責保険金の充当方法（`genpon`／`kakutei`）
- 死亡事案：相続分、死亡慰謝料の本人分と近親者分の配分、固有の損害の帰属、労災・年金の控除額の基準時、生活費控除率

## 未対応

- 代襲相続・相続放棄・内縁配偶者（扶養利益構成）は検証していない。相続分と続柄を手で決めれば表には入るが、請求原因の補足主張は個別に書く。
- 訴状のPDF化はスクリプトでしない。Opuさんが作成者情報を残さない方法でPDFにする（mintsマニュアル別紙3）。
